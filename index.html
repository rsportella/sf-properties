Gerador de Secure Properties para MuleSoft (Mule 4)

O MuleSoft Secure Properties Generator é uma ferramenta online para criptografar e descriptografar propriedades seguras (secure properties) usadas em aplicações MuleSoft e Mule 4. Em vez de baixar o JAR da Secure Properties Tool e rodar comandos com Java, você faz tudo no navegador: escolhe o algoritmo, informa a chave, cola o valor e copia o resultado no formato ![valor_criptografado].

Ela serve para proteger senhas de banco de dados, tokens de API, client secrets e as credenciais de integrações com o Salesforce, que não devem ficar em texto puro em arquivos de configuração, em repositórios Git ou no CloudHub.

  • Criptografa valores avulsos, arquivos YAML inteiros e arquivos quaisquer.
  • Suporta AES, Blowfish, DES, DESede (3DES) e RC2, nos modes CBC, CFB, ECB e OFB, com IV aleatório opcional.
  • Sem instalação, sem Java e sem linha de comando: roda direto no navegador.
  • Gratuito e de código aberto (MIT).

Como criptografar propriedades no MuleSoft em 4 passos

  1. Escolha a aba e a operação. Use String para um valor, YAML para um arquivo inteiro e Encrypt para criptografar.
  2. Selecione algoritmo e mode. Para o padrão do Mule, mantenha AES e CBC. Ligue o IV aleatório se a sua aplicação usar useRandomIVs="true".
  3. Informe a chave e o valor. Use uma chave de no mínimo 16 caracteres (32 para AES-256) e digite a senha, o token ou o client secret a proteger.
  4. Copie o resultado para o arquivo de propriedades. Clique em Gerar, copie o texto ![...] e cole no YAML, entre aspas. Na aplicação, leia com ${secure::sua.propriedade}.

Quer o caminho completo, incluindo o módulo no pom.xml, o Secure Properties Config e a chave no CloudHub? Veja o manual passo a passo de Secure Properties no MuleSoft.

Algoritmos e modes de criptografia suportados

AlgoritmoModesChaveIndicação
AESCBC, CFB, ECB, OFB128, 192 ou 256 bitsPadrão do Mule e recomendado para projetos novos
BlowfishCBC, CFB, ECB, OFBaté 448 bitsCompatibilidade com projetos existentes
DESede (3DES)CBC, CFB, ECB, OFB192 bitsCompatibilidade com sistemas legados
DESCBC, CFB, ECB, OFB64 bitsLegado, evite em projetos novos
RC2CBC, CFB, ECB, OFB128 bitsLegado, evite em projetos novos

O padding é PKCS5/PKCS7. Sem IV aleatório, o IV é fixo e igual aos primeiros bytes da chave; com IV aleatório, ele vai na frente do texto cifrado, como na ferramenta oficial.

MuleSoft e Salesforce: proteja as credenciais das suas integrações

A MuleSoft faz parte da Salesforce e é uma das formas mais usadas de integrar o Salesforce com ERPs, bancos de dados, APIs e outros sistemas. Nessas integrações, o Salesforce Connector precisa de dados como usuário, senha, security token e client secret do aplicativo conectado, e esses valores não devem aparecer em texto puro no projeto.

Com secure properties, você criptografa cada credencial com este gerador e deixa só o valor cifrado no arquivo de configuração:

salesforce:
  username: "usuario@empresa.com"
  password: "![valor_criptografado]"
  securityToken: "![valor_criptografado]"
  clientSecret: "![valor_criptografado]"

No fluxo Mule, a leitura usa o prefixo secure::, por exemplo ${secure::salesforce.password}. A chave de descriptografia fica fora do código e é informada só na execução.

Perguntas frequentes sobre Secure Properties no MuleSoft

O que são secure properties no MuleSoft?

São propriedades de configuração sensíveis (senhas, tokens, chaves de API, client secrets) guardadas de forma criptografada em arquivos YAML ou .properties de um projeto Mule 4. No arquivo, o valor cifrado fica entre ![...] e o módulo Secure Configuration Properties o descriptografa em tempo de execução, usando uma chave informada no deploy.

Como criptografar uma propriedade do Mule 4 sem usar o JAR da Secure Properties Tool?

Use a aba String desta página: escolha Encrypt, o algoritmo (AES por padrão) e o mode (CBC), informe a chave, digite o valor e clique em Gerar. Copie o resultado ![...] para o seu arquivo de propriedades. A ferramenta oficial é um JAR executado por linha de comando com Java; aqui o mesmo trabalho é feito no navegador.

Como funciona o prefixo secure:: no Mule?

Dentro da aplicação, as propriedades do arquivo seguro são lidas com ${secure::nome.da.propriedade}. Propriedades comuns continuam sendo lidas sem prefixo, com ${nome.da.propriedade}.

Minha chave e meus valores são enviados para algum servidor?

Não. A criptografia roda no seu navegador, e a chave, os valores e os arquivos não são enviados para nenhum servidor. O site pode medir o uso (páginas visitadas e opções escolhidas) somente com o seu consentimento, e nunca coleta a chave nem o conteúdo que você processa.

Qual algoritmo e mode devo usar?

Em projetos novos, use AES no mode CBC com IV aleatório e uma chave de 32 caracteres (AES-256). DES, RC2 e os modes ECB, CFB e OFB estão disponíveis por compatibilidade com projetos já existentes.

Qual é o tamanho mínimo da chave?

São necessários 16 bytes (24 para DESede/3DES). Com exatamente 32 caracteres, o AES usa 256 bits; com outros tamanhos, usa AES-128 com os 16 primeiros bytes. A chave precisa ser exatamente a mesma que a aplicação Mule recebe na execução.

Funciona no Anypoint Studio, no Mule on-premises e no CloudHub?

Os valores gerados podem ser usados em qualquer aplicação Mule 4 que utilize o módulo Secure Configuration Properties. A chave é informada na execução: no Studio (argumentos da VM), na linha de comando do Mule ou nas propriedades do Runtime Manager, no CloudHub. O manual mostra cada caso.

Por que a descriptografia falha na minha aplicação Mule?

As causas mais comuns são chave diferente da usada na criptografia, algoritmo, mode ou IV aleatório diferentes, e um espaço depois do ] no arquivo. A seção de erros comuns do manual traz a lista completa.

Isso tem relação com o Salesforce?

A MuleSoft faz parte da Salesforce e é muito usada para integrar o Salesforce com ERPs, bancos de dados e APIs. As credenciais dessas integrações (usuário, senha, security token e client secret) são exatamente o tipo de dado que deve ficar em secure properties. A ferramenta, porém, é independente: não tem vínculo com a MuleSoft nem com a Salesforce.

A ferramenta é gratuita e de código aberto?

Sim. É gratuita e de código aberto sob a licença MIT, e o código está no GitHub.
